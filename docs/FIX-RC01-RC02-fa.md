# اصلاح مرحله سوم: حفظ هویت پیام در صف

## اصلاح‌شده

RC01 و RC02: `order_id` و `message_type` از `send_message` تا متد داخلی request و هر دو شاخه fallback شبکه/API منتقل می‌شوند. شاخه تراکنشی checkout نیز همان مقادیر را به enqueue می‌دهد؛ آن‌ها به بدنه HTTP بله اضافه نمی‌شوند.

بنابراین پیام مدیریتی نوع‌دار پس از خطای شبکه، HTTP ناموفق یا پاسخ نامعتبر، دیگر صرفاً به علت گم‌شدن نوعش در قرنطینه پیام بی‌نوع قرار نمی‌گیرد. ردیف همچنان کنترل مقصد فعلی مدیر را دارد. مسیر پیام سفارش، شناسه سفارش را حفظ می‌کند؛ کنترل مالک فعلی سفارش تضعیف نشده است.

دکمه‌های اینلاین و متن در عبور API→صف→worker حفظ می‌شوند. اجرای worker از queue_on_fail=false استفاده می‌کند؛ شکست ارسال مجدد نباید ردیف صف تازه بسازد. شکست درج صف به‌عنوان موفقیت گزارش نمی‌شود.

## عمداً تغییرنکرده

RC03 هنوز جداگانه باز است: برخی پاسخ‌های ربات از ابتدا نوع صریح ندارند. این اصلاح نوع گمشده را حفظ می‌کند، ولی برای پیام فاقد نوع مجوز تازه جعل نمی‌کند. ردیف‌های قدیمی و تازه بی‌نوع همچنان متوقف می‌شوند؛ برای پاسخ‌های تازه باید نوع، دامنه مقصد و انقضای مناسب در تولیدکننده تعیین شود. اختصاص خودکار admin_order یا آزادکردن همه پیام‌های بی‌نوع راه‌حل امنی نیست.

قرنطینه پیام انبوه قدیمی، کنترل اتصال مشتری و مقصد مدیر، مجوز گزارش‌ها و پشتیبانی تغییر نکرده‌اند. توقف‌های ناشی از این کنترل‌ها همچنان عمدی‌اند. خطای مبهم تحویل و شکست checkpoint در RC08 نیز با حفظ نوع پیام حل نمی‌شود.

## آزمون

۲۸ بررسی جدید در `tests/api-queue-contract.php` با API و worker واقعی افزونه، و فقط WordPress transport/DB شبیه‌سازی‌شده:

- خطای شبکه، HTTP 503، پاسخ ok=false و JSON نامعتبر؛
- چهار context تراکنشی checkout/new order/status؛
- عبور واقعی پیام از fallback تا worker، نه دو mock جدا؛
- حفظ نوع، شناسه سفارش، متن و دکمه‌ها؛
- پیام چندقطعه‌ای؛ عدم ثبت مجدد بازگشتی در worker؛
- شکست درج صف؛ حفظ قرنطینه بی‌نوع و رد مقصد مدیر حذف‌شده.

مجموع **۴۵۲ بررسی PHP و ۹ تست JavaScript موفق**. سه فایل PHP تغییرکرده با parser PHP 7.4 بررسی شدند. در harness ممیزی، RC01/RC02 اکنون رفتار صحیح را بررسی می‌کنند و RC03 همچنان بازتولید می‌شود. دو ایراد تاریخی رابط نیز همچنان باز هستند.

زمان backoff در DB مصنوعی این تست مستقل از ساعت واقعی فیلتر نمی‌شود؛ این آزمون قرارداد انتقال پیام است، نه آزمون زمان‌بندی واقعی MySQL. تست سایت واقعی و بله زنده انجام نشده است. فایل ZIP قبلی بازسازی نشده؛ اصلاح در سورس پروژه است.
