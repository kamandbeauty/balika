# قدم اول پنل: نتیجه معتبر و ایمنی پیام انبوه

- تمام شاخه‌های ذخیره گزینه‌های تنظیمات اصلی، مقدار نهایی را بررسی می‌کنند و بین شکست، بدون تغییر و موفقیت فرق می‌گذارند. زمان‌بندی گزارش یا پیام موفق تولید secret پس از شکست ذخیره ادامه نمی‌یابد.
- ورودی فرم‌های اصلی یک بار unslash می‌شود و ورودی آرایه‌ای غیرمنتظره رد می‌شود.
- ارسال انبوه مقصدهای بله را یکتا می‌کند و تعداد ثبت موفق و ناموفق صف را جدا گزارش می‌دهد؛ تعداد اتصال‌ها دیگر با وعده دریافت پیام نمایش داده نمی‌شود.
- هر فرم ارسال انبوه شناسه تصادفی وابسته به مدیر با اعتبار ۳۰ دقیقه دارد. قفل دیتابیس مانع اجرای هم‌زمان همان شناسه است؛ شناسه قبل از اولین درج مصرف می‌شود. شکست مصرف شناسه یا دریافت قفل، ارسال را متوقف می‌کند.
- شناسه عملیات در نوع پیام صف ثبت می‌شود. این هنوز سامانه کامل مدیریت کمپین نیست.

## محدودیت‌ها

جلوگیری از تکرار مربوط به **همان فرم** است؛ فرم تازه برای ارسال عمدی بعدی مجاز است. دو فرم مستقل یک کمپین واحد محسوب نمی‌شوند. در قطع فرایند پس از مصرف شناسه، ارسال ممکن است ناقص بماند؛ تکرار کور همان عملیات مجاز نیست و بازیابی خودکار بخش باقی‌مانده هنوز وجود ندارد. هشدار رابط این محدودیت را توضیح می‌دهد. تحویل exactly-once توسط API تضمین نشده است.

خواندن یکجای مخاطبان فعلاً باقی است؛ پردازش کمپین‌های بزرگ به شکل قطعه‌ای مرحله جداگانه است. این تغییر سیاست توقف عمومی، مجوز اتصال مشتری یا همه ریسک‌های ممیزی قبلی را حل نمی‌کند. بررسی ذخیره مربوط به تنظیمات اصلی است، نه ادعای بازنویسی همه فرم‌های زیرماژول‌ها.

## اعتبارسنجی

۲۹۳ بررسی PHP موفق، شامل ۱۵ آزمون جدید برای شکست ذخیره، بدون تغییر، کوتیشن ورودی، مقصد تکراری، بازپخش درخواست، شکست کلی/جزئی صف، قفل مشغول، شکست مصرف شناسه، فرم نامعتبر و مجوز/nonce. نحو دو فایل تغییرکرده با PHP 7.4 parser و diff whitespace بررسی شد.

آزمون‌ها شبیه‌سازی‌شده‌اند؛ وردپرس زنده، MySQL چنداتصالی، کش پایدار و بله واقعی در این مرحله آزمایش نشده‌اند. بسته نصب تازه ساخته و روی سایت نصب نشده است.
