# قدم دوم: کار روزانه رهگیری گروهی

- فیلتر همه سفارش‌ها، دارای کد یا بدون کد اضافه شد. فیلتر قبل از صفحه‌بندی اعمال می‌شود؛ ردیف‌های یک صفحه صرفاً در مرورگر پنهان نمی‌شوند.
- جست‌وجوی دقیق بر اساس شناسه داخلی سفارش، تلفن صورتحساب، نام یا نام خانوادگی؛ این جست‌وجو فعلاً جست‌وجوی آزاد/بخشی یا شماره سفارشی سفارش نیست. شناسه با ارقام فارسی هم پذیرفته می‌شود.
- فیلترها در لینک‌های صفحه‌بندی و بازگشت پس از ثبت حفظ می‌شوند.
- تعداد ردیف‌های ویرایش‌شده نمایش داده می‌شود و مرورگر هنگام خروج با تغییر ثبت‌نشده هشدار می‌دهد؛ ثبت خود فرم هشدار خروج ندارد. نمایش هشدار تابع محدودیت‌های مرورگر است.
- خطاهای سرویس ثبت همراه ورودی برای همان مدیر تا ۱۰ دقیقه در transient سرور نگه داشته می‌شوند؛ داده در localStorage مرورگر ذخیره نمی‌شود. خطا کنار ردیف قابل مشاهده است و اگر سفارش از زمان فرم قبلی تغییر نکرده باشد، ورودی برمی‌گردد.
- برای سفارش تغییرکرده، فرم اطلاعات تازه سفارش را نشان می‌دهد و پیش‌نویس قدیمی خودکار روی snapshot تازه نشانده نمی‌شود. خلاصه خطا/کد در بالای جدول باقی می‌ماند؛ تأیید جایگزینی باید دوباره انجام شود.
- دکمه «ثبت» و ورود بدون تیک ردیف حفظ شده‌اند. فیلتر تاریخ و جست‌وجوی آزاد هنوز اضافه نشده‌اند.

## ملاحظات و آزمون

فیلتر متادیتا برای ذخیره‌سازی کلاسیک از hook دیتاستور و برای HPOS از meta_query استفاده می‌کند. سازگاری واقعی هر دو در وردپرس/ووکامرس نصب‌شده همچنان به تست staging نیاز دارد؛ HPOS meta_query به نسخه پشتیبان آن نیاز دارد.

۳۰۲ بررسی PHP و ۹ تست JavaScript موفق بودند. آزمون‌های افزوده، ساخت query، ورودی نامعتبر، برگرداندن ورودی ناموفق، جلوگیری از جایگزینی پیش‌نویس کهنه و هشدار خروج را پوشش می‌دهند. آزمون query به معنی اجرای SQL واقعی هر دو دیتاستور نیست. نحو PHP 7.4 دو فایل تغییرکرده نیز بررسی شد.

این مرحله نصب یا انتشار روی سایت نیست. پیش‌نویس خطا وابسته به مدیر است و عملیات بعدی همان مدیر می‌تواند آن را جایگزین کند؛ بازیابی چندتب مستقل هنوز پیاده نشده است. خطاهای کلی مجوز/nonce/config، پیش از اجرای سرویس ثبت هستند و مانند خطای ردیف بازیابی نمی‌شوند.
