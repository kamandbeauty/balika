# اصلاح مرحله چهارم: پاسخ تازه ربات با دامنه مجوز و انقضا

## قرارداد جدید

تولیدکنندگان پاسخ تعاملی از `send_reply` استفاده می‌کنند؛ این متد با `send_message` عمومی فرق دارد و پیام ناشناخته را خودکار مجاز نمی‌کند. پاسخ کوتاه ابتدا مستقیم با fallback خاموش ارسال می‌شود. اگر ارسال شکست بخورد، فقط یک ردیف `bot_reply` با مقصد و مجوز مشخص ثبت می‌شود. پاسخ بلند از ابتدا به صف چندقطعه‌ای می‌رود.

مهلت پاسخ ۱۵ دقیقه از زمان ساخت آن است؛ retry یا ارسال قطعه بعدی مهلت را تمدید نمی‌کند. اطلاعات داخلی مجوز در بدنه درخواست بله ارسال نمی‌شوند. worker قبل از هر تلاش/قطعه، انقضا و دامنه را بررسی می‌کند؛ نقض آن ردیف را با علت مشخص متوقف می‌کند.

## دامنه‌ها

- **public:** فقط راهنماها و پیام‌های وضعیت غیرشخصی تولیدکنندگان شناخته‌شده، از جمله راهنمای اتصال و پیام خطای توکن. این مجوز مشاهده سفارش یا گزارش مالی نیست.
- **orders:** فهرست حداکثر پنج سفارش همراه با hash مالک هنگام تهیه متن. پیش از ارسال مجدد باید هر سفارش همچنان به همان چت متصل و مالک فعلی با snapshot سازگار باشد. قطع اتصال یا تغییر مالک مانع ارسال متن قبلی می‌شود.
- **admin:** پاسخ خصوصی به فرمان مدیریتی؛ شناسه شخص باید همچنان در اشخاص مجاز یا گیرندگان خصوصی مدیر ثبت باشد. برخلاف broadcast، صرفاً «دریافت گزارش درخواستی توسط شخص مجاز» است.
- **catalog:** ماژول ربات فعال باشد و محصولات درج‌شده همچنان عمومی باشند. تغییر قیمت/موجودی متن ذخیره‌شده را بازتولید نمی‌کند؛ متن snapshot کوتاه‌عمر است.

تولیدکنندگان وبهوک، فهرست سفارش، منوی/گزارش خصوصی مدیر، راهنمای اتصال مدیر، پاسخ شماره تلفن و کاتالوگ به این قرارداد منتقل شده‌اند.

## موارد عمداً دست‌نخورده

- پیام قدیمی یا ارسال عمومی فاقد نوع همچنان قرنطینه می‌شود؛ همه ردیف‌های بی‌نوع به public/admin تبدیل نشده‌اند.
- پاسخ گروهی، از جمله گزارش مدیریتی درخواست‌شده توسط مدیر در گروه، مستقیم و بدون صف retry باقی است. صرف شناسه گروه برای ساخت مجوز خصوصی کافی نیست؛ در خطای شبکه باید فرمان دوباره فرستاده شود.
- پاسخ‌های کنترلی پشتیبانی که از قبل queue_on_fail=false داشتند همان رفتار را دارند. پیام‌های صندوق و رونوشت مدیر guard اختصاصی خود را حفظ می‌کنند.
- پیام موفق دوباره وارد صف نمی‌شود؛ شکست درج صف نتیجه false دارد. انقضای پاسخ با تلاش مجدد عمومی قابل دورزدن نیست.

## محدودیت

قفل اتمیک با تمام تغییرات تنظیمات/مالکیت اضافه نشده است. تغییر بعد از بررسی یا درخواست API آغازشده قابل برگشت نیست. نتیجه مبهم شبکه و شکست checkpoint هنوز مسئله RC08 است؛ این مرحله تضمین exactly-once نمی‌دهد. پس از ۱۵ دقیقه، پاسخ صف‌شده ارسال نمی‌شود و کاربر باید فرمان را دوباره بفرستد. با worker پنج‌دقیقه‌ای و صف شلوغ ممکن است پاسخ پیش از نوبت ارسال منقضی شود.

## آزمون

۲۷ بررسی تازه: ۲۰ آزمون قرارداد API واقعی→صف واقعی→worker با DB/transport مصنوعی، و ۷ آزمون تولیدکنندگان وبهوک برای عدم ارسال اطلاعات سفارش/مالی با scope عمومی.

پوشش شامل انقضا، تغییر مقصد، انقضا میان قطعات، حذف مدیر، قطع اتصال مشتری، تغییر مالک، خصوصی‌شدن محصول، غیرفعال‌شدن کاتالوگ، رد گروه و scope ناشناخته، عدم ارسال metadata داخلی به بله و حفظ قرنطینه پیام‌های قدیمی است.

مجموع **۴۷۹ بررسی PHP و ۹ تست JavaScript موفق**؛ نحو ۱۳ فایل تغییرکرده با PHP 7.4 parser بررسی شد. ممیزی RC03 اکنون ایجاد پاسخ تازه نوع‌دار را تأیید می‌کند؛ این به معنی آزادشدن send_message بدون نوع نیست. RC04، RC05، RC08 و دو ایراد رابط هنوز باز هستند.

تست WordPress/MySQL/Bale زنده انجام نشده و ZIP قبلی بازسازی نشده است.
