# اصلاح مرحله هشتم: صفحه‌بندی کاتالوگ (A08)

صفحه‌بندی دیگر داخل شرط وجود محصول در صفحه فعلی نیست. پس از دریافت موفق کاتالوگ، اگر بیشتر از یک صفحه وجود داشته باشد یا کاربر در صفحه‌ای بعد از صفحه اول باشد، ناوبری قبلی/بعدی نمایش داده می‌شود؛ حتی اگر محصولات همین صفحه خالی باشند.

- صفحه اول خالی با صفحات بعدی: امکان رفتن به صفحه بعد برقرار است.
- صفحه بعدی خالی پس از کاهش تعداد صفحات: دکمه قبلی برای برگشت باقی می‌ماند؛ بعدی غیرفعال است. انتقال خودکار به صفحه اول اضافه نشده است.
- کاتالوگ خالی بدون صفحه دیگر: پیام خالی و دکمه نمایش همه محصولات باقی‌اند؛ ناوبری بی‌استفاده نمایش داده نمی‌شود.
- هنگام بارگذاری یا خطای درخواست: صفحه‌بندی پنهان می‌شود تا بر اساس پاسخ قبلی جابه‌جایی انجام نشود.

فیلتر محصول، endpoint کاتالوگ، checkout و پرداخت تغییر نکرده‌اند. این اصلاح قابلیت دسترسی به صفحات موجود را برمی‌گرداند و تعداد صفحات گزارش‌شده از سرور را بازتعریف نمی‌کند.

## بررسی

چهار تست تعاملی جدید JSDOM روی **bundle ساخته‌شده افزونه**: رفتن از صفحه اول خالی به صفحه دوم دارای محصول و بازگشت، برگشت از صفحه خارج از تعداد جدید، کاتالوگ کاملاً خالی و پنهان‌بودن ناوبری هنگام loading/error.

`npm run build` موفق؛ **۱۳ تست JavaScript و ۵۶۷ بررسی PHP موفق**. ممیزی A08 به بررسی رفتار صحیح تبدیل شد. A09 هنوز در ممیزی بازتولید می‌شود و اصلاح نشده است. `git diff --check` بدون ایراد بود.

فایل `balika/assets/commerce/storefront.js` بازسازی شده است، اما ZIP آزمایشی قبلی هنوز بازسازی نشده. این تست‌ها مرورگر واقعی موبایل یا WordPress/WooCommerce زنده نیستند. ریسک timeout مبهم شبکه از مرحله RC08 همچنان باز است.
