# اصلاح مرحله هفتم: شکست checkpoint پس از ارسال صف (RC08)

## تغییر رفتار

worker پس از کنترل مجوزهای فعلی و پیش از تماس با بله، وضعیت ردیف را از pending به uncertain تغییر می‌دهد. این تغییر شرطی است و باید دقیقاً یک ردیف را تغییر داده باشد؛ در شکست ثبت، هیچ تماس ارسال انجام نمی‌شود.

- پذیرش API و ثبت موفق نتیجه: وضعیت sent می‌شود.
- پذیرش قطعه میانی: شماره قطعه بعدی و بازگشت به pending در **یک update** ذخیره می‌شوند.
- شکست ثبت sent یا پیشرفت قطعه: وضعیت uncertain باقی می‌ماند؛ worker بعدی آن را انتخاب نمی‌کند.
- توقف ناگهانی اجرای worker بعد از ثبت پیش‌نشانگر: ردیف uncertain باقی می‌ماند؛ حتی اگر هنوز تماس HTTP شروع نشده باشد. این انتخاب محافظه‌کارانه ممکن است نیازمند بررسی پیام واقعاً ارسال‌نشده هم باشد.
- پیام موفقیت در لاگ فقط بعد از ثبت موفق sent نوشته می‌شود.

وضعیت uncertain با متن «نتیجه تحویل ثبت نشده» در تاریخچه گزارش‌ها و شمارش آن در نمای صف نمایش داده می‌شود. پاک‌سازی معمول ۳۰روزه آن را حذف نمی‌کند. تلاش مجدد عمومی و تلاش مجدد تک‌گزارش آن را آزاد نمی‌کنند. برای این وضعیت دکمه ارسال مجدد کورکورانه اضافه نشده است؛ ابتدا باید مقصد بله و متن/قطعه پیام بررسی شود. تغییر دستی status به pending بدون بررسی می‌تواند دوباره پیام بسازد.

## مرز ادعا

این اصلاح **تکرار خودکار ناشی از شکست checkpoint ثبت sent/قطعه یا قطع اجرای worker** را می‌بندد. exactly-once ادعا نمی‌شود: تراکنش مشترکی بین MySQL و API بله وجود ندارد، و شناسه idempotency یا استعلام تحویل مستند در دسترس نیست.

رفتار خطای معمول transport که API مقدار false برمی‌گرداند همچنان backoff قبلی است. بنابراین **timeout مبهم شبکه** (ممکن است بله پذیرفته باشد ولی پاسخ به ما نرسیده باشد) و fallback ارسال مستقیم هنوز می‌توانند باعث تکرار شوند. این ریسک جداگانه با checkpoint حل نمی‌شود و باز است. بازگردانی پایگاه‌داده/تغییر دستی ردیف نیز خارج از تضمین این اصلاح است.

## آزمون

۸ بررسی تازه با fault injection: شکست ثبت پیش‌نشانگر (بدون ارسال)، بازیابی آن، شکست ثبت sent، شکست checkpoint قطعه و exception شبیه‌ساز قطع transport؛ در سه حالت آخر، اجرای دوباره worker و دو مسیر retry نباید ارسال را تکرار کنند. تست‌های قبلی موفقیت قطعه‌ها و backoff نیز برقرارند.

مجموع **۵۶۷ بررسی PHP و ۹ تست JavaScript موفق**. ممیزی RC08 اکنون یک تماس API و باقی‌ماندن ردیف uncertain را تأیید می‌کند. نحو شش فایل PHP این مرحله با parser PHP 7.4 بررسی شد. دو تست ممیزی رابط هنوز A08 و A09 را بازتولید می‌کنند و اصلاح آن‌ها باقی است.

محیط تست DB/transport مصنوعی و PHP WASM است؛ قطع واقعی اتصال MySQL، crash سیستم، بله زنده و سایت WordPress آزمایش نشده‌اند. ZIP قبلی بازسازی نشده است.
